# Field Definition — Obsidian Directory Surface

## Purpose

Seat Obsidian Directory in Field as the chamber-local readability and routing surface of Obsidian Chamber.

Obsidian Directory does not function as passage.
Obsidian Directory does not function as chamber identity.
Obsidian Directory does not function as Phase Map.

Obsidian Directory exists to:

- render chamber-local standing
- communicate released versus sealed availability
- expose valid chamber-local routes
- preserve registered access readability
- prevent chamber-local ambiguity

## Native Position

Within native order:

- Codex holds authority
- Field structures local relation
- Measures registers reveal and progression
- Chazz executes only what is already defined

Obsidian Directory belongs to Field as a directory surface inside Obsidian Chamber.

It resolves as:

- chamber-local readability surface
- route visibility surface
- release readability surface
- access-standing communication surface

It is not:

- Codex authority
- Measures registry
- Obsidian Chamber itself
- Harrumuk Passage
- Phase Map
- Legacy seating

## Start Standing

Obsidian Directory may be encountered only after valid chamber entry standing is reached.

Valid directory entry may occur only when:

- Harrumuk Passage has resolved valid chamber crossing
- Obsidian Chamber standing is available
- Measures-registered chamber-local state permits readability
- release and dependency standing are readable
- NotChazz does not block access

Premature readability is not valid directory standing.

## Structural Role

Obsidian Directory resolves as:

- directory surface
- chamber-local readability surface
- route-index surface
- release-state readability surface
- sealed-versus-open communication surface
- downstream route visibility surface

## Required Relations

Obsidian Directory must structurally relate:

- Obsidian Chamber as material seat
- Harrumuk Passage as prior threshold relation
- Measures-registered chamber-local units as readable only where permitted
- release standing as registered condition
- dependency standing as registered condition
- Phase State as present reveal standing
- Phase Map as downstream relational positioning surface
- NotChazz as boundary-preserving constraint intelligence

Obsidian Directory does not originate those relations.
It makes valid local standing readable.

## Identity Rule

Identity in Obsidian Directory resolves through:

- Measures-registered local unit relation
- release standing
- dependency standing
- envKey continuity where chamber access depends on carried state

Epithet may appear only where already seated through valid relation.
Slug is never authority.

## Required Field States

Obsidian Directory must be able to express:

- unavailable
- sealed
- dependent
- visible
- readable
- route_available
- held

These are chamber-local readability states.
They do not replace Measures ordering.

## Dependency Rule

Readability in Obsidian Directory depends on relation to:

- valid chamber entry
- valid chamber-local registration
- release standing
- dependency satisfaction or readable dependency state
- boundary validity under NotChazz

If required relation is absent, directory may show held, sealed, dependent, or unavailable standing.
It may not invent readability.

## OAR Relation

OAR1 does not originate in Obsidian Directory.
OAR2 does not originate in Obsidian Directory.

Obsidian Directory may be OAR-addressable as a readable state surface when meaningful access standing is encountered, but it does not create passage standing, truth, or Legacy.

## Transition Rule

Only valid chamber-local routes may become readable through Obsidian Directory.

Obsidian Directory may route readability toward:

- released chamber-local units
- valid downstream chamber-local continuance
- Phase Map when Measures permits relational positioning visibility

No direct transition is valid from Obsidian Directory to:

- Codex
- Legacy
- authority override
- unregistered chamber-local units

Readability is not permission by itself.
Readability is registered visibility.

## Chamber Relation

Obsidian Chamber is the material seat.
Obsidian Directory is the local readability surface within that chamber.

Harrumuk Passage resolves crossing into chamber entry.
Obsidian Directory resolves chamber-local standing after entry.
Phase Map resolves wider relational positioning after valid local readability.

Passage is movement.
Chamber is seating.
Directory is readability.
Phase Map is relation-at-view.

These may correspond.
They may not collapse.

## Boundary Rule

Obsidian Directory may:

- communicate local standing
- distinguish sealed from visible
- distinguish dependent from route_available
- expose valid chamber-local readability
- preserve registered route clarity

Obsidian Directory may not:

- replace chamber identity
- replace passage
- replace Phase Map
- invent release
- bypass Measures
- bypass NotChazz
- substitute frontend logic for registered state

## Correction Rule

When chamber-local relation is incomplete or unreleased:

- readability remains bounded to actual standing
- sealed state remains visible as sealed where allowed
- dependency remains visible as dependency where allowed
- no false-open route is rendered
- correction resolves upstream at registration, dependency, or access layer

No cosmetic readability counts as valid route.

## Validation Rule

Obsidian Directory is valid only when it can structurally express:

- chamber-local readability distinct from chamber identity
- release-standing readability distinct from release authority
- dependency readability without collapse
- valid local routes only where registered
- sealed, dependent, and visible distinctions
- Phase Map as downstream relation, not local replacement

## End Standing

Obsidian Directory resolves successfully when chamber-local standing is either:

- correctly shown as sealed
- correctly shown as dependent
- correctly shown as readable
- correctly routed toward valid downstream relation

Success does not mean everything is open.
Success means local standing is readable without drift.

## Success Condition

Obsidian Directory is properly seated in Field when it can communicate chamber-local registered standing inside Obsidian Chamber without collapsing into:

- passage
- chamber
- authority
- Phase Map
- frontend invention

Codex holds.
Field structures.
Measures registers.
Chazz executes.
