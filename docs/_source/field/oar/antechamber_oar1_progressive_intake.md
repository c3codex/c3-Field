# Antechamber Contract — Progressive Intake (OAR1 Origin Surface)

## Purpose

Define the **first executable surface** of the system where signal may enter, be structured, and become eligible for passage.

Antechamber is:

- intake surface
- threshold surface
- OAR1 origin point

Antechamber is not:

- Codex
- Measures registry
- final authority

---

## Core Principle

Signal may enter incomplete.  
Signal may not pass incomplete.

---

## I. Entry Condition

Entry into Antechamber requires:

- valid origin
  - Named Individual
  - Institution in Service

No coherence requirement at entry.

All entry begins in **incoherence**.

---

## II. Progressive Intake Model

Antechamber allows staged formation of signal.

Signal may arrive as:

- partial intent
- media only
- text only
- contact only
- unstructured input

System does not reject incomplete signal.

System **holds and builds structure over time**.

---

## III. Required Intake Components (for passage eligibility)

To progress toward passage, the following must resolve:

1. **SRC standing**
   - SRC / SRC1 / SRC2 as applicable

2. **Envelope presence**
   - container established
   - may begin empty, must resolve to structured

3. **envKey generation**
   - persistent access key bound to Envelope

4. **OAR1 attachment**
   - Objective
   - Action
   - Result

If any of the above are incomplete:

→ signal remains in Antechamber  
→ no passage permitted  

---

## IV. OAR1 Formation

OAR1 attaches when:

- minimum intake structure is satisfied
- Envelope exists
- envKey is bound
- initial Objective can be recorded

OAR1 records:

- Objective → declared or inferred intent
- Action → intake handling (upload, entry, binding)
- Result → current standing (held / ready / requires correction)

OAR1 does not:

- validate truth
- seat Codex record

OAR1 establishes **passage readiness state**

---

## V. NotChazz Enforcement

NotChazz monitors:

- structural completeness
- role integrity
- passage eligibility
- routing validity

NotChazz will:

- allow incomplete intake
- block premature passage
- prevent execution outside valid structure
- hold signal in Antechamber until conditions are satisfied

If violation occurs:

- OAR1 remains attached
- signal is held
- correction is required before continuation

---

## VI. Passage Boundary

Signal may exit Antechamber only when:

- SRC is valid
- Envelope is structured
- envKey is active
- OAR1 is attached
- structural integrity is confirmed

Then:

→ Harrumuk Passage becomes available

---

## VII. System Behavior

Antechamber must:

- accept incomplete signal
- build structure progressively
- preserve trace through OAR
- never simulate completion
- never bypass registry requirements

Antechamber must not:

- allow execution beyond threshold
- allow frontend to compensate missing structure
- allow Chazz to invent missing logic
- allow passage without verification
