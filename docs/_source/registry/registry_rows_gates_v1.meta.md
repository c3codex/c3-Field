# Registry Rows Gates

## Purpose

Define the planted gate-row family for the rewritten registry source stack.

This doc preserves the current gate family as thresholded progression units.

A gate row exists to govern bounded progression through constraint and permitted action.

Gate rows do not collapse into:

- spine rows
- chamber-directory rows
- chamberplate
- epithet rows
- ME rows

This doc defines the gate-family content surface.

It does not define:

- row identity shape in general
- geometry rules in general
- structural validity conditions in general
- chamber-directory content
- chamberplate row content
- epithet-family content
- ME-family content

## Scope

For the current rewritten pass, the seated native gate rows are:

- Gate I
- Gate II

Gate 0 remains dissolved and non-native.

This doc is family-specific.
It is not the whole registry stack.

## Native Distinction

Codex holds.
Field structures.
Measures registers.
Chazz executes.

Gate rows remain subordinate to that order.

Nothing in this doc defines authority outside Codex or structure outside Field.

## Gate-Family Rule

Gate rows are:

- planted Measures units
- thresholded progression units
- constraint-bearing
- action-permitting
- sequence-bearing within the gate family

A gate does not merely mark progression.
A gate governs thresholded action through bounded condition.

## Family Distinction

Gate rows remain distinct from:

- spine rows, which are system-known and non-planted
- chamber-directory rows, which communicate chamber-local information
- chamberplate, which is an encounter destination
- epithet rows, which are the 9 role units
- ME rows, which are the 13 function units

A gate may route, constrain, or condition what follows.
It does not replace those other families.

## Access Note

Gate logic remains real even where exhibition access is broader than one exclusive bottleneck.

That means:

- broader access visibility does not erase gate identity
- TempleHome access does not dissolve gate function
- continued gateplate pass-through does not redefine a gate into a directory or chamberplate

Gate rows remain progression units even when exhibition access remains readable from more than one path.

## Conversion Note

Conversion remains completion standing.

Gate rows may participate in progression toward conversion.
They do not themselves equal conversion standing.

A visible or reachable gate is not the same thing as completed conversion.

## Circuit Note

c1, c2, and c3 remain circuit only.

For the current rewritten gate-family pass, the clean reading remains:

- Gate I = c2
- Gate II = c2

That keeps gates in thresholded bounded progression without collapsing them into chamber, material, or directory.

## Material Note

For the current rewritten gate-family pass:

- Gate I = obsidian
- Gate II = obsidian

This remains consistent with their thresholded progression role.
