Definition:
A process is a bounded, repeatable route for a class of work.

A process is not:

* a thread
* a file
* a folder
* a single prompt
* a one-off correction

A process must include:

* named purpose
* start standing
* end standing
* touchpoint sequence
* validation rule
* correction rule
* closeout rule

Process forms when:

* the route is explicit
* the steps are bounded
* validation exists
* the route can repeat without reinvention

Process existence is confirmed when:

* it resolves through 3 process docs or 3 validated thread surfaces
* expected structure is explicit
* standing is declared
* use is clear

Process is used where:

* repeatable work must move without drift
* validation must occur before continuance
* correction and closeout must be preserved
