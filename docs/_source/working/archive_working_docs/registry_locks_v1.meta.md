# Registry Locks

## Purpose

Freeze approved registry distinctions after review so they do not drift during later row expansion, naming refinement, or institutional normalization.

Registry locks protect:

- seated distinctions
- dissolved legacy drift
- family separation
- approved freeze points

Registry locks do not replace:

- registry identity shape
- registry geometry
- row-family docs
- registry constraints

## Scope

This doc freezes approved distinctions for the current registry stack.

It applies to:

- system-known, non-planted spine rows
- planted Measures rows
- naming and identity freeze points
- family-order separation
- institutional readability separation
- current material seating clarifications

This doc does not define:

- structural validity conditions
- row validation logic
- protected geometry bodies
- release state
- asset mapping
- Envelope instance logic
- envKey
- c3_key
- route logic

## Identity Lock

`internal_key` is the stable identity handle.

`display_title` is not authority.
Asset naming is not authority.

Native name remains deferred until class stability is confirmed.

## Identity Freeze Order

Identity freeze order remains:

1. unit class
2. internal_key
3. planted vs non-planted distinction
4. native_name
5. display_title refinement
6. asset attachment

## Classification Lock

A unit may be system-known without being a planted Measures unit.

System-known surfaces do not impersonate planted units.

Gates, epithets, and MEs are planted Measures units.

Gate 0 remains dissolved and non-native.

## Family Order Lock

Family-bound order fields remain separate.

- `surface_order` governs field-spine surfaces
- `gate_order` governs progression units
- `role_order` governs role units
- `function_order` governs function units

No shared installation-wide order is frozen at this stage.

## Institutional Readability Lock

Institutional term describes access-layer function.

Native resolution identifies what the row actually is.

Institutional language does not replace native resolution.
Institutional language does not define authority.
Institutional language does not collapse native distinctions.

## Circuit / Chamber / Material Lock

c1, c2, and c3 resolve to circuit only.

Circuit identifies operational motion and relation.
Circuit does not define chamber.
Circuit does not define material.

Chamber or surface identifies structural or encounter context.
Material identifies embodied seat.

These may relate.
They may not collapse into one another.

## Material Seating Lock

Current seated material clarifications for the working pass:

- Temple = crystal
- Antechamber may use lapis as surface
- Phase Map = null material
- role family and material seat remain distinct
- epithet rows may not be flattened to one family-wide material assignment

## Distinction Lock

The following distinctions remain frozen for the current stack:

- arrival does not equal intake
- intake does not equal passage
- passage does not equal chamber
- chamber does not equal inscription
- inscription does not equal positioning
- system-known does not equal planted
- role family does not equal material family
- circuit does not equal chamber
- circuit does not equal material
