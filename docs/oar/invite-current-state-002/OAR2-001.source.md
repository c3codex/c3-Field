It then *writes* an active `c3_env_share_reference` **before** computing the invitation URL.

For any chosen initiative it calls `initiativeEntryUrl`, which requires exactly one active `system_process_registry` row of `surface_type=initiative_connect_surface` for that initiative, `release_state=released`, `access_state=public`, canonical host, and valid native initiative-surface-host authority. Founders Ground has no such public surface. Its registered `founders_ground_initiative_formation_v1` and `initop_founders_ground_op044_v1` are active, with `invite_context_allowed=true`; but `public_release_authorized=false`, `runtime_release_authorized=false`, and no initiative connect surface row. This is intentional formation-vs-release separation, **not permission to manufacture a public page**. Existing `c3_env_initiative_visibility` has no Founders Ground participant row; operator context is not participation.

Live source-created `c3_env_share_reference` `90c495d0-3588-4d2b-a5bc-bd919b10513b` exists, active, minted 2026-10-16 20:20:05Z, source environment `env_person_eea672f5a7676dad4316755b`, operator provenance `source_initiative_key=founders_ground` and `source_operator_binding_key=initop_founders_ground_op044_v1`.
