# Measures Registry — Lapis Interoperability Route Contract v1

## Contract Purpose

The Lapis Interoperability Route is the transition surface that connects the Right Path (Structure the Environment) to ongoing implementation, SRC continuation, cohort activation, and future runtime alignment routes.

Lapis = relational orientation, positioning, passage, interoperability.

The Interoperability Route does not implement. It routes with governed authority.

## Route Definition

The Lapis Interoperability Route is not a terminal chamber.

It is the surface that bridges:
- The Right Path's Marble Governance Chamber output
- Active SRC continuation
- Runtime cohort and conversion pathways
- Future governed runtime alignment routes

It is the architectural connector of the Measures Registry installation.

| Field | Value |

| DB encounter_keys | `cohort_conversion_encounter`, `c3_field`, `reserve_seat` (convergence points) |

## Branch Interoperability

The Lapis Interoperability Route is where Left Path and Right Path visitors may converge.

| Visitor Standing | Entry Route | Convergence Point |
|---|---|---|
| Left Path — qualified | Marble Commerced Circuit → reserve_seat | `reserve_seat`, `phase_payment` |
| Right Path — structured | Marble Governance → cohort route | `cohort_conversion`, `reserve_seat` |
| Both paths | Assessment complete | `measures_phases_reveal`, `about_measures_registry` |

Convergence is governed. Both paths arrive under their respective contract conditions.

## SRC / Runtime / Cohort Continuation

The Interoperability Route connects to:

1. **SRC continuation** — the SRC (Structured Response Contract) established in `connect_src` carries through to implementation and cohort surfaces. The SRC contact record follows the visitor from intake through circuit activation.

2. **Runtime alignment** — the route anticipates a future runtime alignment surface where the visitor's governed environment is wired into active Measures Registry runtime operations. This surface is held pending a separate OAR2.

3. **Cohort activation** — the `cohort_conversion_encounter` surface carries grouped implementation contracts. Cohort activation requires a seated delivery contract and operator confirmation.

4. **c3 Field connection** — the `c3_field` surface links Measures Registry back to the c3 Field system. The Interoperability Route is where the installation connects outward.

## Future Runtime Alignment Route

A future runtime alignment OAR2 will govern:
- DB_HELD_CODEX_SOURCE_RECORDS alignment to canonical source_key values
- SRC continuation through DB source-reference
- Active runtime interoperability between Measures Registry and governed DB-held sources

This future OAR2 is documented as carried forward from the Deprecation-First Runtime Source Cleanup OAR1.

The Lapis Interoperability Route holds space for this surface without implementing it.

## What the Lapis Interoperability Route Must Not Do

- Implement runtime alignment (that is a future OAR2)
- Activate cohort contracts without delivery contract
- Route visitors back through assessment as a gating mechanism
- Replace the Marble Governance Chamber
- Collapse SRC, SRC1, SRC2, and src as equivalent surfaces
- Treat the route as terminal — it connects, not closes

## Boundary

This contract governs route definition, branch interoperability, SRC continuation, and future route placeholder.

Runtime alignment implementation is a separate future OAR2.

Cohort delivery contract seating is a separate OAR2.

No media, CSS, or DB mutation is authorized by this contract.
