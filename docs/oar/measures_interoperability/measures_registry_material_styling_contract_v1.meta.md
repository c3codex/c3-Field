# Measures Registry — Material Styling Contract v1

## Contract Purpose

The Material Styling Contract defines the visual state and style for each material place in the Measures Registry installation.

Material styling expresses chamber state. It does not author authority. It does not compensate for missing registry state. It does not create passage, recognition, payment, or conversion.

CSS implementation is not authorized by this contract.

## Global Visual Rule

Measures Registry visual style is:

- institutional
- restrained
- audit-grade
- museum-grade
- precise
- material-aware
- quietly geometric
- boardroom-safe
- trust-bearing

**Forbidden across all material places:**

| Forbidden Style | Reason |
|---|---|
| Fantasy UI | Undermines institutional authority |
| Game interface treatment | Incompatible with audit-grade register |
| Excessive glow | Visual hype — breaks museum-grade register |
| Startup hype aesthetics | Incompatible with trust-bearing register |
| Fear-selling red alert dominance | Non-punitive tone governs — alarmism violates it |
| Unbounded mystical spectacle | Visual mysticism ≠ institutional credibility |
| Unverified trust badges | Claims authority that is not registered |
| Pricing implication styling before delivery contract | Boundary violation — payment requires payment OAR2 |
| Activation state styling without governance condition | State must follow contract, not precede it |

## Material Place Visual Definitions

### 1. Epigraph Place

**Visual state:**
- pre-material — no assigned material family
- dark institutional field
- minimal brand mark
- quiet opening geometry
- no CTA clutter

**Style:**
- restrained typography — declarative, spacious leading
- minimal movement — entry gesture only, no looping animation
- subtle crystalline linework — marks threshold without spectacle
- no fantasy portal effect
- no excessive glow or light bloom

**Styling must not:**
- imply assessment or commerce before Temple
- introduce decorative excess at the threshold
- animate in a way that demands attention over content

---

### 2. Temple Path Place

**Visual state:**
- balanced two-path field
- Assess the Environment / Structure the Environment
- branching moment — equal visual weight

**Style:**
- equal visual weight for both paths — no funnel emphasis
- institutional plaque or card treatment — formal surface
- restrained material contrast between paths
- clear visual distinction without hierarchy pressure
- no urgency styling on either path

**Styling must not:**
- visually emphasize one path over the other
- introduce color-coded urgency (red/green = assess now vs. you're ready)
- apply progress indicators implying the visitor is behind
- use sales-funnel visual conventions (highlighted CTA, faded alternative)

---

### 3. Lapis Relational Place

**Visual state:**
- lapis relational field
- orientation and explanation
- About / Structural Drift / Contact / Subscription / Support surfaces

**Style:**
- deep lapis panels — mineral depth, not digital gloss
- thin gold or silver relation lines — lateral surface connectors
- layered editorial surfaces — stacked content cards at publication density
- calm navigation — no aggressive CTAs
- publication-ready readability — serif or editorial sans, generous line height

**Styling must not:**
- rush visitor toward assessment through visual urgency
- treat subscription or contact as conversion-pressure surfaces
- apply marble or obsidian styling to relational surfaces

---

### 4. Crystal/Lapis c3 MAP Place

**Visual state:**
- recognition and assessment protocol
- Measures Assessment Protocol explanation
- pattern visibility
- SRC intake form

**Style:**
- crystal-lapis overlays — transparency and pattern visibility layered
- precise assessment diagram — geometric, not illustrative
- restrained luminous geometry — clarity signal, not spectacle
- audit dashboard clarity — form fields, clean labels, structured layout
- no pricing indicators

**Styling must not:**
- display C1/C2/C3 circuit badges or pricing signals
- use visual excitement cues (sparkle, glow pulse) that imply recognition achievement
- apply marble contract styling before qualification is confirmed

---

### 5. Obsidian Assessment Gate Place

**Visual state:**
- diagnostic readiness gate
- 7-question assessment sequence
- drift exposure output
- risk/routing evidence display

**Style:**
- obsidian field — dark, precise, reduced
- sharp contrast — clear question/answer distinction
- sober diagnostic panels — no decorative excess
- no alarmist red dominance — indicators are informational, not threatening
- progress and standing indicators only where governed by encounter contract

**Styling must not:**
- generate fear through color, motion, or typographic weight
- present drift as failure or shame
- display routing outcomes before assessment completes
- apply marble or lapis styling to the assessment gate

---

### 6. Marble Commerced Circuit Place

**Visual state:**
- qualified asset standing display
- C1 / C2 / C3 Commerced Circuit standing
- 3x33 distribution framework
- delivery/payment surface placeholders

**Style:**
- marble panels — polished, formal, governed weight
- executive contract surface — structured layout, formal type
- circuit badges — formal, not celebratory
- no activation state styling without delivery contract condition
- no payment styling before payment OAR2

**Styling must not:**
- display activated circuit state before delivery contract
- render payment UI as active before phase_payment conditions are met
- use hype styling for circuit standing (no confetti, no celebration animation)
- conflate C1/C2/C3 with readiness phase visual indicators

---

### 7. Right Path Media Passage Place

**Visual state:**
- structure-path media carrier
- video/image orientation
- build-path signal
- passage to Marble Governance

**Style:**
- restrained cinematic media frame — full or near-full field video treatment
- institutional captioning — not stylized subtitle treatment
- no media-as-authority styling — caption and controls are informational
- passage controls only where governed (continue button, mute control)

**Styling must not:**
- present media as authority over encounter content
- use film-festival or entertainment visual conventions
- introduce assessment, intake, or pricing in the media frame
- delay transition past governed auto-advance or continue paths

---

### 8. Marble Governance Place

**Visual state:**
- Structure the Environment — architecture pathway
- contract seating
- cohort/conversion readiness
- implementation-ready signal

**Style:**
- marble-lapis governance surface — marble formal weight, lapis relational depth
- structured modules — contract-forward card layout
- implementation-ready visual treatment — precise, buildable, not speculative
- no execution implied — contract is staged, not activated

**Styling must not:**
- replicate Left Path assessment visual language
- imply circuits are activated through governance styling
- use startup-launch visual conventions
- present cohort surfaces as implemented before delivery contract

---

### 9. Lapis Interoperability Place

**Visual state:**
- continuation and connection
- support / subscription / email
- social automation placeholder
- c3 Field connection

**Style:**
- connective lapis route map — nodes, paths, relation lines
- continuity cards — clean, understated
- understated support path — support is adjacent, not primary
- no automation-active styling before future OAR2

**Styling must not:**
- render email, subscription, or social automation as active
- treat Lapis Interoperability as a terminal surface — it connects, not closes
- use sales-conversion visual conventions at continuity surfaces

---

## Material Styling Boundary

Material styling is a governed contract layer.

This contract does not authorize:
- CSS file modification
- runtime implementation
- DB mutation
- media upload
- audio implementation
- payment, subscription, email, social, or support automation styling as active

CSS implementation waits for its implementation OAR2.
