# OAR2 — Define Measures Registry Public Runtime Boundary v1

## OBSERVED

Measures Registry now has the public education / assessment architecture seated enough to define a bounded public runtime pass.

The Crystal style refinement OAR1 seated the comparison hero, layout hierarchy, component rules, encounter-specific style rules, and density correction. It also confirms public material naming and public C1/C2/C3 exposure remain prohibited.

The Structural Drift publication contract is seated inside the Crystal chamber with active CTA behavior and publication URL resolved from seated metadata.

The Crystal explainer video media mapping is seated, with the talking-head passage video preserved as distinct from the Questions video.

The commerce circuit deliverables OAR1 hardened the internal pathways:

C1 = AI Environment Review
C2 = MAP the Environment
C3 = Foundational Measures Registry Cohort

C1 is review from assessment/survey inputs, C2 includes bounded c3 MAP Runtime Audit, and C3 includes runtime audit plus guided implementation pathway. Pricing remains unchanged and private/governed; both public paths are preserved.

Runtime final pass remains blocked across the executed OAR1 stack.

## ALIGNED

This OAR2 defines the current Measures Registry runtime boundary as:

public-facing runtime only

Public runtime includes both public paths:

LEFT: Assess the Environment
RIGHT: Understand the Environment

System-related chambers remain held.

Governed commerce remains hidden/private.

MAP execution remains held.

Guided MAP asset creation remains held.

Findings delivery remains held.

Conversion and certification remain held.

This boundary preserves native distinction: source, structure, registry, execution, actor, system, visibility, and permission do not collapse.

Frontend remains renderer only. Cody may implement src strictly from OAR2 and may not infer routing, invent fallback truth, decide encounter meaning, or compensate for missing DB structure.
