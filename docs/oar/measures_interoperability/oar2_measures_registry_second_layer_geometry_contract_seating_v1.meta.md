## GEOMETRY FUNCTIONS

Second Layer Geometry must define:

- adjacency
- dependency
- passage
- mirror / isomorphic relation
- return
- conversion
- boundary

### 1. Adjacency

Defines which material places may sit beside one another.

Example:

Lapis Relational Place may sit beside:
- c3 MAP explainer
- About Measures Registry
- Structural Drift / Paragraph
- Contact / Connect
- Subscription
- c3 Field support

### 2. Dependency

Defines what must resolve before a place may open.

Example:

Obsidian Assessment Gate depends on:
- Temple path choice
- Lapis orientation
- c3 MAP recognition / explanation

### 3. Passage

Defines how movement occurs between places.

Example:

Assess the Environment
→ Lapis Relational Passage
→ Crystal/Lapis c3 MAP Place
→ Obsidian Assessment Gate
→ Marble Commerced Circuit Place

### 4. Mirror / Isomorphic Relation

Defines how Measures Registry mirrors Measures of Inanna without copying content.

Example:

Epigraph opens.
Temple branches.
Passages carry relation.
Material chambers govern function.
Measures registers standing.
Codex holds authority.

### 5. Return

Defines where unresolved signal goes.

Example:

Incomplete c3 MAP / SRC signal
→ returns to Lapis Relational Place or Contact / Support
not Marble Commerced Circuit activation

### 6. Conversion

Defines where assessed material becomes qualified asset standing.

Example:

c3 MAP qualifies.
Obsidian exposes.
Marble receives qualified assets.
C1 / C2 / C3 circuit standing requires delivery contract.

### 7. Boundary

Defines what cannot cross without a future OAR2.

Example:

No payment activation without payment contract.
No subscription automation without subscription contract.
No social automation without distribution contract.
No runtime alignment without runtime OAR2.
No CSS alignment without material styling OAR2.
No tonal bed implementation without media/audio route.
