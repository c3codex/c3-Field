# OAR1 — Repair Measures Registry Public URL Resolution and Assessment Runtime Routing v1

## OBJECTIVE

Repair Measures Registry public URL resolution and assessment runtime routing.

Bind `/ai-operations-assessment` to the active assessment entry flow. Redirect `/structural-drift` to the active `/undrifted` public surface. Govern `/map-integrity-governance` to a held state until required registry records are seated. Restore SPA route fallback for Cloudflare Pages.

## ACTION

### 1. Added SPA fallback for Cloudflare Pages

Created `public/_redirects`:

```
/* /index.html 200
```

Cloudflare Pages serves static files before evaluating `_redirects` rules. Route-specific `index.html` files (generated by `generate-registry-route-heads.cjs`) continue to be served with their pre-baked SEO metadata. The `_redirects` rule applies only for paths without a matching static file, including `/map-integrity-governance` and any other path not covered by a route head.

### 2. Added `/map-integrity-governance` to `ROUTE_UNIT_KEYS`

In `MeasuresRegistryRuntimeRegistered.tsx`, added:

```typescript
"/map-integrity-governance": "map_integrity_governance_landing",
```

Because `map_integrity_governance_landing` does not exist in `measures_registry` (the required encounter, registry entry, public title, route alias, and directory binding are not yet seated), the surface dispatcher enters the "landing_unit_missing" governed held state:

```
Landing page registry unit is not seated.
map_integrity_governance_landing is required before this route may render as public truth.
```

This state renders automatically when `landingUnitsLoaded` is true and the DB record is absent. No records were invented. No frontend truth was hardcoded. The held state resolves when Codex seats the `map_integrity_governance_landing` registry record.

`/map-integrity-governance` was NOT added to `generate-registry-route-heads.cjs`. No route head is generated for that path. Until the registry record is seated, the route falls to the `_redirects` SPA fallback and the held state is served.

### 3. Added `/structural-drift` → `/undrifted` redirect

In `MeasuresRegistryRuntimeRegistered.tsx`, added a mount-time `useEffect`:

```typescript
useEffect(() => {
  if (window.location.pathname === "/structural-drift") {
    window.location.replace("/undrifted")
  }
}, [])
```

`window.location.replace` is used (not `href` assignment) so the `/structural-drift` entry is replaced in history — the back button does not loop back to the deprecated route.

The `/structural-drift` route head continues to be generated by `generate-registry-route-heads.cjs` (it requires a seated `structural_drift_landing` registry record). Its SEO metadata already carries `canonical_url: https://measuresregistry.com/undrifted`. The client-side redirect fires on mount and the user lands at `/undrifted`.

`/undrifted` is the active public-facing publication surface. `/structural-drift` is now a governed deprecated alias.

## BLOCKER REPORT

The following blocker is not resolved by this OAR and must be tracked separately:

**Assessment carry-forward is session-state only.**

- Assessment result (`evalReport`) is computed in component state and not durably written to `src_intake_request`.
- No active contact-capture surface is seated between the assessment result and Marble entry that writes a durable record before the passage video.
- The `measures_iis_eval_gate1_capture` table is written on contact form submission (after assessment), but this write depends on session state being present (`evalReport` and `evalEmailArtifact` must be non-null). If the page is refreshed between assessment completion and contact submission, the carry-forward is lost.
- A partial reconstruct exists: on `map_integrity_governance` surface load, if `evalCaptureId` is present but `evalReport` is null, the component fetches the capture record from DB and reconstructs `evalReport`. This covers the case where the user navigates back or reloads after successful contact submission.
- The gap is: between assessment score computation and contact form submission, no durable write exists.

This blocker does not prevent the current assessment flow from completing. It prevents durable carry-forward in the case of mid-session page reload before contact capture.
