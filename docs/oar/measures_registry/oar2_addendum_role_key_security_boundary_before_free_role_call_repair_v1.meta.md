# OAR2 Addendum - Role Key Security Boundary Before FREE role_call Repair

## PURPOSE

Amend role_call repair standing before implementation.

Clarify that the nine native roles are structural encounter authorities only.

Clarify that role_key for login, gating, permission, or access control is separate and must be secure, system-generated, and non-public.

Pause any FREE role_call implementation that treats public native role names as secure role keys.

Nothing is invented.

## STANDING CORRECTION

The nine native roles are not AI role profiles.

The nine native roles are not human user profiles.

The nine native roles are not login roles.

The nine native roles are not permission groups.

The nine native roles are structural authorities used by role_call.

## NATIVE ROLE IDENTIFIERS

Native role identifiers may include:

- obsidian_gatekeeper
- obsidian_examiner
- obsidian_witness
- lapis_guide
- lapis_scribe
- lapis_steward
- marble_resolver
- marble_cartographer
- marble_sealkeeper

These are public architectural identifiers.

They are not authentication credentials.

They are not secure access tokens.

They are not login keys.

## ROLE_KEY SECURITY BOUNDARY

If role_key is used for:

- login
- gating
- permission
- access control
- authorization of protected actions
- secure passage
- role-bound private state

then role_key must be:

- system-generated
- non-guessable
- non-public
- stored securely
- never inferred from display copy
- never inferred from native role names
- never hand-authored in public source
- never exposed to frontend as authority

## AI ROLE PROFILE BOUNDARY

AI role profiles are separate from the nine native roles.

An AI role profile may support a task, voice, workflow, or assisted behavior.

An AI role profile is not one of the nine native roles unless a future OAR explicitly registers that relationship.

No AI role profile may be treated as a secure role_key.

## FREE REPAIR IMPLICATION

FREE may resolve native role_call for encounter authorization.

FREE may not treat native role names as secure credentials.

FREE may not use native role names for login or private gating.

FREE may only use native roles to determine encounter standing, passage requirements, passage modes, and renderer authorization.

Secure login/gating role_keys require a separate OAR and secure generation path.

## REQUIRED ACTIONS

1. Record this addendum before continuing FREE role_call repair.
2. Confirm any in-progress OAR does not treat native role names as secure role_keys.
3. Confirm role_call implementation remains structural only.
4. Confirm secure role_key generation is held for a future OAR.
5. Confirm AI role profiles remain separate.
6. Do not wire login, permission, or secure access behavior in the FREE repair OAR.

## VALIDATION

Return OAR1 evidence showing:

- addendum recorded
- nine native roles remain structural only
- role_key security boundary recorded
- AI role profile boundary recorded
- FREE repair held from using native role names as secure keys
- no secure role_key generation implemented
- no login/gating implementation added
- no frontend exposure of secure authority

## NOTCHAZZ FLAGS

Raise NotChazz if:

- native role names are used as secure role_keys
- AI role profiles are treated as native roles without OAR
- public role names are used for login or gating
- secure role_keys are hand-authored
- secure role_keys are exposed to frontend
- FREE repair implements access control without separate OAR
- operator is governed instead of the work body

## CLOSE

Record role_key security boundary.

Then resume FREE role_call repair as structural encounter authorization only.

The system aligns.
