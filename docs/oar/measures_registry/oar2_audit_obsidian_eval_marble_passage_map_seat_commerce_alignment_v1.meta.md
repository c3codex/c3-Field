# OAR2 — Audit Obsidian Eval, Marble Passage, and MAP-SEAT Commerce Alignment v1

## OBSERVED

Measures Registry requires a current standing audit before seating MAP / SEAT commerce alignment contracts.

The assessment flow and related public surfaces have active or recently corrected seams.

This audit must determine actual current standing before mutation across:

    Obsidian eval content
    scoring-to-circuit continuity
    passage media contract
    Marble reveal content
    MAP / SEAT / Direct / Mapped / Federated / Foundational language
    runtime reveal behavior
    styling containment

No landing page, SEO, social, hero, publication, or route-head mutation is authorized by this OAR2.

This OAR2 is an audit-only instruction surface.

## ALIGNED

Authority order remains:

    Codex -> Field -> Measures -> OAR2 -> Chazz -> Cody -> src

Codex is the authority.

Field structures relation.

Measures registers sequence and reveal.

Frontend renders only what is seated.

This OAR2 does not authorize implementation.

This OAR2 does not authorize DB mutation.

This OAR2 does not authorize runtime mutation.

This OAR2 does not authorize media replacement.

This OAR2 does not authorize pricing, payment, c3 Key, SRC, conversion, certification, DAO, permission, recognition, distribution, or Marble readiness standing.

The purpose is to determine what must change before a later seating OAR.

## ROUTED

### 1. Audit Obsidian Eval standing

Verify current:

    result title
    answer-derived risk copy
    scoring outputs
    CTA language
    whether protocol or pricing is revealed too early
    whether C1/C2/C3 leaks publicly
    whether content aligns to structural AI drift risk
    whether result surface remains in frame
    whether CTA remains accessible

Expected:

    Obsidian shows risk and aligned continuation only.
    Obsidian does not reveal MAP pricing.
    Obsidian does not reveal protocol deliverables.
    Obsidian does not expose public C1/C2/C3.
    Obsidian remains visually Obsidian.

### 2. Audit scoring contract standing

Verify:

    AI Operations Assessment scoring exists
    scoring resolves to internal circuit or pathway
    internal circuit maps to Direct / Mapped / Federated where applicable
    result preserves internal circuit through continuation
    public copy does not show C1/C2/C3
    all-low-risk answers do not falsely produce severe drift language
    answer-derived risk copy reflects structural AI drift risk

Expected:

    One completed assessment resolves to one internal pathway.
    Internal pathway may later govern matched Marble reveal.
    Public result uses MAP path recommendation language, not C1/C2/C3.

### 3. Audit passage media standing

Verify:

    current passage video/media key
    current passage script/content if seated
    whether it explains MAP / SEAT transition correctly
    whether it belongs between Obsidian eval and Marble reveal
    whether replacement media is required
    whether media is mapped through governed media mapping
    whether runtime uses registered media rather than hardcoded media path

Expected:

    Passage explains transition from risk indicators into Measures Assessment Protocol reveal.
    Passage does not expose pricing/payment/c3 Key/SRC prematurely.
    Passage remains registry-driven.

### 4. Audit Marble reveal standing

Verify current:

    protocol reveal content
    Direct / Mapped / Federated language
    MAP / SEAT language
    assessment pricing, if present
    deliverables, if present
    credit rule, if present
    Foundational SEAT language
    Foundational c3 Seats language
    whether multiple protocol options are shown at once
    whether matched protocol is revealed only after passage

Expected:

    Marble reveals only the matched Measures Assessment Protocol.
    Marble does not show a public comparison table unless explicitly seated.
    Marble does not reveal unmatched pathways.
    Marble does not create payment, c3 Key, certification, conversion, DAO, or permission standing.

### 5. Audit runtime sequencing

Verify:

    DB/registry-driven sequencing
    no frontend-owned reveal logic
    no hardcoded public C1/C2/C3
    no option comparison table if only one matched protocol should show
    no landing-route side effects
    no direct bypass from assessment to Marble without passage
    no bypass of contact gate
    no bypass of result gate

Expected flow:

    Assessment
    -> Obsidian Eval / result
    -> Passage Media
    -> Marble Matched Protocol Reveal

### 6. Audit styling and containment

Verify:

    Obsidian remains Obsidian
    Marble remains Marble
    result/eval surface stays in frame
    no laptop overflow
    no inaccessible CTA
    single-card reveal where only one matched protocol is shown
    no table if only one matched protocol is shown
    CTA follows sitewide button contract
    mobile and desktop remain usable

Expected:

    Material styles remain distinct.
    CTA remains accessible.
    Content remains contained.
