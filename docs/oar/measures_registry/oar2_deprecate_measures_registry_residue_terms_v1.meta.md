# OAR2 — Deprecate Measures Registry Residue Terms v1

## OBSERVED

Measures Registry currently carries active-language residue from prior path architecture.

The residue appears across threshold meanings, route labels, chamber assumptions, and public-facing institutional language.

Deprecated or rejected terms include:

- understand_failure
- build_coherence
- system evaluation
- cohort conversion
- Evaluate the Environment
- Structure the Environment
- educational diagnostic
- cohort conversion encounter as public path identity
- Crystal Chamber as institutional/public label
- Marble Governance Chamber as institutional/public label

The corrected institutional threshold is:

- LEFT THRESHOLD = Assess the Environment
- RIGHT THRESHOLD = Understand the Environment

Current architecture requires language separation before governed layout seating.

Assessment must remain the scored 7-question public/institutional baseline surface.

c3 MAP must remain the governed runtime audit that identifies institutional structural drift and delivers governed actions / implementation.

Measures Conversion must remain the verified completion condition required before Registry Certification.

Pricing, payment, wallet connect, temporary payment provider, c3 Key assignment, temporary c3 Key assignment, SRC binding, permission standing, recognition, conversion, certification, DAO standing, and distribution standing must remain governed commerce surfaces and not public-facing institutional copy.

Seed Concordance confirms native order as Codex -> Field -> Measures -> Chazz, with Codex holding authority, Field structuring relation, Measures registering sequence/access/reveal, and Chazz rendering/routing/validating within role.

The 21 of Coherence confirms role integrity, native distinction, and verification before recognition as required constraints.

## ALIGNED

This deprecation pass corrects the active language seam before any new governed layout is seated.

It preserves:

- Codex = authority
- Field = schema / relation
- Measures = registry / sequence / reveal
- Chazz = systems validation / routing
- Cody = bounded executor
- src = renderer only

Frontend must not author truth or infer meaning from deprecated labels.

Cody’s role contract states that frontend renders seated state only and may not invent routing, fallback truth, release state, or encounter meaning.

OAR Lifecycle requires Cody to execute only from OAR2, with no thread instructions and no completed process without OAR1.

This OAR2 does not seat the final governed layout yet.

It only prepares the language field by marking residue inactive and defining allowed replacement terms for the next operative concordance update.

### 2. Establish active threshold language

The active institutional threshold resolves only as:

LEFT THRESHOLD:

Assess the Environment

RIGHT THRESHOLD:

Understand the Environment

### 3. Define Assess the Environment

Assess the Environment is the public/institutional scored 7-question baseline assessment.

It establishes:

- minimal institutional AI governance baseline
- awareness of current structural deficiencies
- preliminary readiness/risk posture
- recommended C1 / C2 / C3 c3 MAP commerce circuit

It does not:

- complete c3 MAP
- perform runtime audit
- deliver governed implementation
- bind SRC automatically
- trigger payment
- issue c3 Key
- assign temp c3 Key as final standing
- grant permission
- grant recognition
- complete Measures Conversion
- certify registry standing

### 4. Define Understand the Environment

Understand the Environment is the public education / orientation path.

It may include:

- c3 MAP education
- Measures Conversion education
- Structural Drift publication
- governed AI optimization orientation

It does not:

- score
- assess
- route payment
- assign c3 Key
- bind SRC
- grant permission
- grant recognition
- complete conversion
- certify registry standing

### 5. Define c3 MAP distinction

c3 MAP is the governed runtime audit.

It identifies:

- institutional structural drift
- authority gaps
- role boundary failures
- AI/runtime surfaces
- review pathway failures
- implementation risk
- required governed actions

It delivers:

- governed findings
- action requirements
- implementation routing
- environment correction pathway
- conversion readiness structure

c3 MAP is not the 7-question baseline assessment.

### 6. Define Measures Conversion distinction

Measures Conversion remains the verified completion condition.

It is not:

- assessment completion
- c3 MAP participation
- payment
- implementation activity alone
- self-declared readiness
- public-facing claim

Measures Conversion is not partial progression, self-declared status, or presentation output; it is recognized only when required passage, sequencing, and right-angle relation are true.

### 7. Define Registry Certification distinction

Registry Certification may only follow:

Assessment baseline
-> c3 MAP runtime audit
-> governed implementation
-> Measures Conversion
-> verification
-> Registry Certification

Recognition follows verification.
