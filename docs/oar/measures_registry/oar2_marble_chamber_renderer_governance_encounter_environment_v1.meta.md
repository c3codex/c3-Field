# OAR2 — Marble Chamber Renderer

## OBSERVED

Encounter Renderer now supports:

- Obsidian environment rendering
- Lapis environment rendering
- Chamber Router dispatch by EncounterEnvironment
- RenderableEncounter-only renderer contracts

The next environment is Marble.

Marble is the governance environment.

## PURPOSE

Marble renders governance encounters.

It does not assess.

It does not orient.

It does not create authority.

It renders governed action surfaces already seated in Registry standing.

## ENVIRONMENT RESPONSIBILITY

Marble establishes:

- governance
- resolution
- institutional action
- MAP continuation
- governed optimization
- report orientation
- implementation readiness

Marble does not determine release standing.

Marble does not determine payment standing.

Marble does not grant certification, conversion, permission, or recognition.

## RENDER CONTRACT

Create:

src/measures_registry/encounter_renderer/chambers/MarbleChamberRenderer.tsx

Input:

RenderableEncounter

Output:

Governance encounter presentation.

No authority logic.

No registry mutation.

No assessment logic.

No Lapis orientation logic.

## INITIAL SURFACES

Initial marble surfaces may include seated encounters for:

- map_integrity_governance
- governed optimization
- MAP continuation
- structured findings / report orientation
- marble passage / governance entry

Render only what encounterDef.metadata and mediaByRole provide.

If governance data is not seated:

render honest governed renderer gap.

No invented action.

No placeholder authority.

Marble may render:

- governance title
- institutional finding summary

- action readiness framing
- seated CTA labels

Marble may not:
