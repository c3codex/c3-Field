# OAR2 — Measures Registry Branding + Frontend Dependency Audit v1

## OBSERVED

Measures Registry now has:

- approved lapis branding direction
- approved emblem package
- approved palette
- seated assessment/runtime content
- seated Structured Environment media
- DB-first process enforcement
- public/runtime terminology audit

Brand assets have now been added to the Supabase `measures-registry` bucket.

The next required action is not broad frontend mutation.

The next required action is a governed audit of:

- branding alignment
- frontend dependency standing
- unseated media/content
- hardcoded runtime truth
- design token drift
- DB/media dependency integrity

Current concern:

the frontend may still contain:

- hardcoded colors
- hardcoded copy
- hardcoded URLs
- fallback runtime truth
- unseated media dependencies
- ungoverned content dependencies
- bucket-presence-only media assumptions

The goal is to identify all remaining frontend/runtime dependencies before additional styling or launch polish work proceeds.

## ALIGNED

Codex is authority.

Frontend renders governed state.

Bucket presence alone is not authority.

Branding must become governed runtime standing, not scattered frontend styling.

Approved Measures Registry branding package now defines the stable visual authority direction.

Approved wording:

Measures Registry
Integrity Governance for AI Accelerated Systems

Approved palette:

- Obsidian: #0E0E17
- Deep Lapis: #1F2F8D
- Lapis Night: #101A4D
- Silver Frame: #D7DBE3
- Crystal Star: #F2F4F8
- Marble Accent: #C7CBD2

Approved branding rules:

- Use lapis as primary field color behind the mark.
- Use silver frame as stable outer authority surface.
- Keep the star bright and mineral, not glowing or soft.
- Reserve marble for supporting text and formal document surfaces.
- Use line watermark emblem when full mineral mark is too heavy.
- Do not fill, bevel, or glow watermark surfaces.

No broad styling mutation should proceed until dependency standing is reviewable.

This OAR2 is primarily:

- audit

- dependency visibility
- branding standing verification

This OAR2 does not authorize:

- broad frontend redesign
- uncontrolled runtime rewrite
- DB authority mutation
- arbitrary style replacement
- encounter restructuring
