# OAR2 — Normalize Phase Map as Ritual Release Surface and Refine Semantic Copy

## OBSERVED

Phase Map diagnosis confirmed the current surface is behaviorally coherent in parts but semantically mixed.

Operator clarified the intended primary function:

    Phase ritual release exact

Operator also clarified the intended secondary function:

    universal cadence sequence

Meaning:
- released chamberplates follow exact release cadence
- cadence is not grouped by family
- cadence follows ceremonial release order across the installation

## ALIGNED

Codex remains authority.
Field structures release relation.
Measures registers release standing, cadence, and interaction.
Chazz normalizes semantic meaning before visual redesign.
Cody executes only from this OAR2.

This OAR2 authorizes:
- semantic normalization
- interaction normalization
- Phase Map copy refinement
- cadence emphasis
- legend simplification
- release interaction repair

This OAR2 does not authorize:
- major visual redesign
- topology redesign
- unrelated traversal changes
- invented release logic

## ROUTED

### 1. Normalize primary Phase Map role

Phase Map must resolve primarily as:

    ritual release surface

Phase Map governs:
- released standing
- held/sealed standing
- ceremonial cadence
- release sequencing
- encounter relation

### 2. Normalize node interaction semantics

Released/open nodes should be directly interactable.

Viewed history may remain available for:
- styling
- visitation indicators
- historical memory

Viewed history must not block interaction for already released/open nodes unless a specific governed release rule explicitly requires it.

### 3. Preserve ceremonial release cadence

Cadence must represent exact ceremonial release order, not grouped family progression.

Cadence sequencing must preserve release order across families.

Example:

    gate_1
    → next released chamberplate
    → next released chamberplate
    → next released chamberplate

### 4. Simplify explanatory copy

Replace verbose instructional copy with concise ceremonial description.

Header:

    PHASE MAP

Description:

    The Phase Map reveals released encounter units in ceremonial relation.

    Held units remain visible until seated by exact release.

Avoid onboarding tone, tutorial phrasing, behavioral instructions, dashboard language, and excessive explanatory text.

### 5. Simplify legend semantics

Legend should express one semantic axis clearly.

Preferred release-state legend:
- Released
- Current Cadence
- Held
- Sealed

Do not overload material meaning and release meaning at the same visual priority.

### 6. Preserve existing ceremonial traversal structure

Preserve:
- Kumurrah return continuity
- Harrumuk initiation continuity
- Gate Passage reuse continuity
- Inanna non-Phase-Map standing
- Temple Home routing structure

### 7. Validation

After normalization, Cody must validate:
- released nodes are interactable
- held/sealed nodes remain visible but unavailable
- cadence order reflects ceremonial release sequence
- current cadence visually distinguishes from general release state
- simplified copy deployed
- simplified legend deployed
- no onboarding/dashboard semantic drift remains
- traversal continuity preserved
- no unintended route regressions introduced
- local/deployed standing reported
