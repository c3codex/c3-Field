# OAR2 — Public Encounter Language Audit + Runtime Terminology Alignment

## OBSERVED

Measures Registry has reached a stage where internal/native governance language is visibly bleeding into public encounter surfaces.

Examples observed:

- SRC
- soft SRC intake
- implementation-facing semantics
- DB/process terminology appearing in runtime UI
- governance-native labels exposed directly to public-facing encounters

The system architecture itself remains coherent.

The drift exists specifically between:

- internal/native system language
and
- public encounter language

This is now affecting:
- chamber readability
- institutional clarity
- encounter cohesion
- public trust surface quality
- runtime semantic consistency

The issue is not DB structure.

The issue is translation-layer alignment.

## ALIGNED

Internal/native terminology and public/runtime terminology are not the same layer.

Native/internal language exists for:
- Codex
- Field
- Measures
- schema
- OAR
- runtime execution
- governance process
- DB authority

Public encounter language exists for:
- institutional readability
- chamber clarity
- CTA continuity
- assessment comprehension
- runtime pacing
- guided progression

The public runtime must feel:
- coherent
- intentional
- calm
- institutional
- measured

It must not feel:
- database-exposed
- acronym-heavy
- implementation-facing
- process-leaking
- schema-authored

This OAR2 establishes a formal runtime terminology audit and translation alignment process.

## ROUTED

### 1. Runtime terminology audit

Cody must inspect all Measures Registry public runtime surfaces and identify:

- internal/native terms exposed publicly
- inconsistent CTA language
- implementation-language bleed
- DB/process semantics exposed in UI
- unstable naming patterns
- duplicated meaning across different labels
- inconsistent encounter wording

Audit surfaces include:

- intro
- landing
- recognition passage
- assessment explainer
- Assessment Chamber
- Structured Environment passage
- Structured Environment
- intake/CTA surfaces
- audio controls
- progression buttons
- completion states
- dispatch/archive references

### 2. Produce terminology review set

Cody must return a reviewable terminology map including:

- current runtime term
- suspected internal/native source
- current runtime usage location
- recommended public-facing replacement
- consistency/conflict notes

Required structure:

CURRENT TERM
→ LOCATION
→ INTERNAL SOURCE
→ RECOMMENDED PUBLIC TERM
→ NOTES

### 3. Establish public encounter language layer

Cody must help identify a coherent public-facing language layer for Measures Registry.

The public layer should prioritize:

- institutional clarity
- environmental coherence
- assessment continuity
- restrained governance language
- cinematic encounter continuity
- operational readability

The runtime should feel:
- governed
- measured
- intentional

not:
- process-exposed
- database-authored
- acronym-dependent

### 4. Preserve native/internal language boundaries

Internal/native terminology must remain preserved in:

- DB
- OAR
- schema
- governance process
- implementation docs
- runtime contracts
- media maps
- encounter defs
- release/access systems

This OAR2 does not rename internal authority structures.

It governs runtime/public-facing translation surfaces only.

### 5. Identify CTA inconsistencies

Audit and normalize:

- Continue
- Enter
- Begin
- Assessment
- Evaluation
- Environment
- Structured Environment
- Audio
- Dispatch
- Intake
- Recognition
- Passage
- Chamber

Determine:
- where continuity exists
- where terms drift
- where redundant labels exist
- where institutional readability weakens

### 6. Review language before mutation

No large-scale runtime copy mutation should occur yet.

This OAR2 is:
- audit
- mapping
- review
- terminology alignment preparation

Return the terminology structure first for operator review before major runtime rewrite execution.

### 7. Produce recommended encounter vocabulary set

Cody should recommend a stable public-facing vocabulary layer for:

- progression actions
- assessments
- structured pathways
- governance concepts
- dispatch/archive references
- intake surfaces
- completion states
- audio controls
- institutional guidance

The vocabulary should feel:
- coherent
- durable
- scalable
- institutional
- restrained

## CODY ROLE

Cody may:

- inspect runtime surfaces
- identify terminology drift
- map internal/public language collisions
- propose public-facing replacements
- produce terminology review sets
- recommend consistency improvements
- identify duplicate semantics

Cody may not:

- rename DB authority structures
- mutate runtime copy globally without review
- collapse native/internal semantics
- invent unsupported governance meaning
- rewrite encounter flow structure during audit phase

## VALIDATION

This OAR2 resolves successfully when:

- runtime terminology drift is identified
- public/internal language boundaries become visible
- CTA inconsistencies are mapped
- database/process-language bleed is identified
- coherent public-facing replacements are proposed
- a stable encounter vocabulary layer begins forming
- runtime/public language becomes reviewable separately from native/internal architecture
