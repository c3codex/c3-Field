# OAR2 - Coherence Optics Grammar Registry v1

## OBSERVED

The Runtime Coherence Optics chamber now renders live runtime data from seated structures.

Current standing:

runtime data = seated / Field-derived
visual code = frontend-authored composition

This creates a drift condition.

The data is governed, but the visual grammar is still owned by src.

As a result, Cody can preserve runtime truth while still producing optics that feel compositionally off-track, because the rules for visual coherence are not yet seated in Field or registered through Measures.

## ALIGNED

Frontend must not author the optics grammar.

src should render registered visual grammar the same way it renders registered runtime state.

The missing layer is:

Coherence Optics Grammar Registry

This registry should define how seated runtime relation becomes visible through:

- material behavior
- spatial hierarchy
- node placement
- vector rendering
- fracture visibility
- correction arcs
- marble inscription
- perceptual emergence
- density limits
- composition presets

The visual surface should resolve from Field/Measures, not component taste.

## ROUTED

### 1. Define optics grammar registry structure

Create or propose registry structures for:

- optic grammar key
- material family
- geometry role
- visual behavior
- spatial rule
- relation rule
- density rule
- fracture rule
- correction rule
- inscription rule
- reveal priority
- renderer contract

### 2. Seat material behavior rules

Register material behaviors:

Crystal = authority stillness / coherence pulse / center-held source
Obsidian = threshold / refusal / blocked passage / fracture tension
Lapis = relation / vectors / dependency / continuity pathways
Marble = inscription / evidence / closure memory / witnessed continuity

No material behavior may be hardcoded as frontend preference.

### 3. Seat spatial hierarchy rules

Register perceptual order:

1. Crystal coherence felt first
2. Lapis relation perceived second
3. Obsidian fracture tension perceived third
4. Marble inscription continuity discovered fourth
5. Detailed lineage encountered last

### 4. Seat visual density rules

Register density limits so the chamber does not collapse into dashboard reporting.

Rules should include:

- text secondary to geometry
- labels minimal unless inspected
- no equal visual urgency
- no excessive panels
- relation must be perceivable before explanation
- fracture must remain visible without overwhelming center authority

### 5. Seat relation rendering rules

Register how relations render:

- upstream
- downstream
- corrective
- convergent
- divergent
- dependency
- blocked-return
- unresolved
- sealed

Each relation type must map to a visual behavior without inventing relation.

### 6. Seat composition presets

Create registry-driven composition presets, such as:

- field_lens
- rooted_orbit
- mandala_runtime
- inscription_ring
- fracture_return

The frontend may select a preset only from registered standing.

### 7. Preserve runtime boundary

This OAR2 does not authorize:

- frontend-owned truth
- mutation
- automation
- public execution
- hardcoded visual authority
- service-role exposure
- invented runtime state

The registry defines optics grammar.
src renders it.

## CODY ROLE

Cody may:

- propose schema or manifest structure
- implement optics grammar loading
- refactor visual components to consume registered grammar
- preserve existing runtime data bindings
- reduce hardcoded composition logic
- expose missing grammar honestly

Cody may not:

- invent grammar outside the registry
- hardcode material semantics
- silently replace runtime state
- fabricate visual relation
- collapse Field/Measures into frontend styling
- treat mockup composition as authority

## VALIDATION

This OAR2 resolves successfully when:

- visual grammar is defined outside component taste
- material behavior is registry/manifest-driven
- spatial hierarchy is registered
- relation rendering rules are registered
- frontend renders grammar rather than inventing it
- existing runtime data remains preserved
- no new mutation or automation is introduced
