runtime observability
? transition governance
? operator-gated automation bridge
? optics expression

However, the hardest surface to reconstruct outside the current environment is not the frontend.

The DB currently carries:

- authority standing
- relation structure
- registry continuity
- OAR lineage
- transition history
- seeded references
- branch eligibility
- correction pressure
- runtime contracts
- evidence continuity

Without a governed reconstruction passage, the system cannot be coherently reseated without drift.

## ALIGNED

The next protection layer is:

DB Source Relation Map + Reconstruction Passage

This does not migrate the DB.

This does not mutate the DB.

This defines:

- what relations exist
- what dependencies must hold
- what order preserves continuity
- what runtime surfaces depend on
- what must remain true for reseating

Purpose:

preserve continuity during future reconstruction, transfer, migration, or reseating

The DB is not inventory.

The DB is relational continuity.

## ROUTED

### 1. Define DB authority relations

Map required authority surfaces including:

- Codex authority records
- Field relation structures
- Measures registry standing
- OAR lineage
- transition records
- seeded references
- release/access standing
- runtime governance standing
- runtime contract relations

### 2. Define reconstruction dependencies

For each source relation define:

- required table
- required keys
- parent relation
- dependency relation
- runtime consumer
- seeded reference dependency
- validation requirement
- reconstruction order

### 3. Define reconstruction passage boundary

The reconstruction passage may include:

- schema relation maps
- table standing
- key continuity maps
- dependency structures
- validation queries
- reconstruction sequencing
- runtime dependency standing

The reconstruction passage may not expose:

- secrets
- service-role credentials
- protected execution intelligence
- private environment values
- authority-bypassing logic

### 4. Define reconstruction order

Required reconstruction order:

schema relations
? authority standing
? registry standing
? relation continuity
? release/access standing
? OAR lineage
? transition continuity
? seeded references
? runtime contracts
? validation passage

### 5. Define validation passage

Reconstruction is not valid unless it confirms:

- table continuity
- key continuity
- parent-child relation continuity
- release standing continuity
- OAR lineage continuity
- transition continuity
- seeded reference standing
- runtime contract readability
- no duplicate authority surfaces
- no frontend fallback authority

### 6. Preserve source-first discipline

Nothing enters or leaves the DB without source relation mapping.

Future:
- migration
- restore
- reseating
- replication
- continuity recovery

must begin from this relation map.

### 7. Preserve authority distinction

The relation map describes continuity.

It does not become authority.

Codex remains authority.

The reconstruction passage preserves reseating continuity only.
