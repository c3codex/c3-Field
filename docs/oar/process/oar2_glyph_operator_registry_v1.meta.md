# OAR2 - Glyph Operator Registry v1

## OBSERVED

Coherence Optics Grammar is now registered outside component-owned visual taste.

Current standing:

runtime state ? optics grammar ? surface render

This creates the correct next threshold:

registered glyph operators

The chamber currently relies on labels, arcs, classes, and material callouts to express relation.

However, c3-native optics needs compact visual compression so seated state can be perceived before being read.

## ALIGNED

Glyphs are not decoration.

Glyphs are registered visual operators.

A glyph may express:

- material behavior
- relation type
- passage state
- correction standing
- fracture condition
- closure seal
- evidence memory
- reveal priority

Glyphs must resolve from registered optics grammar and seated runtime state.

Frontend may render glyphs.

Frontend may not invent glyph meaning.

## ROUTED

### 1. Define Glyph Operator Registry

Create or propose a registry/manifest structure for:

- glyph_key
- material_family
- operator_type
- relation_type
- state_condition
- visual_form
- render_priority
- meaning_contract
- allowed_surface
- renderer_class
- fallback_behavior

### 2. Seat material glyph operators

Register initial operators:

Crystal glyph
- coherence pulse
- authority stillness
- center-held source

Obsidian glyph
- threshold
- blocked passage
- refusal
- correction required
- fracture tension

Lapis glyph
- relation
- vector
- dependency
- continuity pathway
- field positioning

Marble glyph
- inscription
- evidence
- closure seal
- witnessed continuity
- memory sediment

### 3. Seat relation glyph operators

Register relation glyph behavior for:

- upstream
- downstream
- corrective
- convergent
- divergent
- dependency
- blocked-return
- unresolved
- sealed

### 4. Preserve visual compression discipline

Glyphs must reduce label burden.

They should make state perceivable without requiring immediate text explanation.

Text may remain available as secondary inspection.

### 5. Preserve runtime truth

Glyphs may only render when the seated runtime condition exists.

No simulated glyph state.

No decorative glyphs pretending to be operational.

### 6. Preserve material distinction

Glyph operators must not collapse material behavior.

Each glyph must retain its native material role and meaning contract.

### 7. Preserve read-only boundary

This OAR2 does not authorize:

- mutation
- automation
- public execution
- invented runtime state
- frontend-owned truth
- service-role exposure

Glyph registry defines visual operators.

src renders them.

## CODY ROLE

Cody may:

- create glyph operator registry structure
- wire glyph rendering to existing optics grammar
- replace excess labels with glyph expressions
- preserve inspection text as secondary
- preserve all runtime bindings
- expose missing glyph mappings honestly

Cody may not:

- invent glyph meaning in components
- hardcode operational glyph semantics outside registry
- render glyphs without seated state
- use glyphs as decoration when no state exists
- collapse material distinctions
- remove runtime truth

## VALIDATION

This OAR2 resolves successfully when:

- glyph operators are registered outside component taste
- material glyphs resolve from grammar/state
- relation glyphs reduce label burden
- glyphs render only from seated conditions
- inspection text remains secondary
- runtime bindings remain preserved
- no mutation or automation is introduced
