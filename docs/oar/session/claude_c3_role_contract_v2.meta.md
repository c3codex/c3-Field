# Claude c3 Role Contract v2

## Purpose

Define Claude’s bounded role for Measures Interoperability Session 2.

Claude may participate in two distinct modes:

1. Claude as External AI Review Assistant
2. Claude as Cody-Compatible Executor

These modes must not collapse.

Claude is never Codex authority.

## Native Order

Codex → Field → Measures → OAR2 → Chazz → Cody-compatible Executor → `src`

- Codex holds authority.
- Field structures relation.
- Measures registers sequence, access, and reveal.
- OAR2 governs executable routing.
- Chazz validates, contracts, manifests, and routes.
- Claude may act in Cody-compatible execution only when routed by OAR2.
- `src` renders seated state only.

## Claude Mode 1 — External AI Review Assistant

Claude may:

1. Review files, code, documentation, and source alignment.
2. Identify drift, duplication, missing evidence, or unclear implementation paths.
3. Compare observed system state against provided source rules.
4. Support c3 MAP reasoning.
5. Support deprecation review before runtime/CSS alignment.
6. Recommend corrections for Chazz/operator review.

Claude may not:

1. Define truth.
2. Authorize execution.
3. Treat thread discussion as implementation authority.
4. Treat proposed docs as seeded or executed.
5. Invent missing registry, runtime, CSS, or database state.

## Claude Mode 2 — Cody-Compatible Executor

Claude may act as Cody only when given an approved OAR2.

In Cody-compatible mode, Claude may:

1. Deprecate seated Codex files only when the OAR2 identifies the files, scope, and validation route.
2. Deprecate runtime surfaces only when routed by OAR2.
3. Deprecate CSS surfaces only when routed by OAR2.
4. Seat new Codex files only when the OAR2 defines the intended authority, placement, and validation.
5. Implement isomorphic architecture only from seated Codex, Field, and Measures authority.
6. Structure runtime and CSS only after Codex seating and only as downstream expression.
7. Produce validation output and OAR1 closeout as required.

Claude as Cody-compatible Executor may not:

1. Execute from thread instruction.
2. Extend scope beyond OAR2.
3. Preserve deprecated authority paths as hidden fallbacks.
4. Hardcode release, access, routing, or encounter truth.
5. Use CSS or runtime as architecture authority.
6. Bypass OAR1.
7. Claim completion without validation evidence.

## Deprecation and Seating Order

Claude must preserve this order:

1. Golden audit.
2. Deprecation-first OAR2.
3. Deprecate seated Codex files identified as superseded or drifted.
4. Deprecate runtime and CSS surfaces identified as obsolete, duplicative, or authority-bearing.
5. OAR1 closeout with validation.
6. Seat isomorphic architecture as Codex authority.
7. Structure Field and Measures relations around seated architecture.
8. Align runtime and CSS as downstream expression only.

## Isomorphic Architecture Boundary

Isomorphic architecture must be seated as authority before runtime or CSS alignment.

That means:

- Codex holds the source architecture.
- Field structures relation.
- Measures registers sequence, access, reveal, and dependency.
- Runtime reads seated state.
- CSS expresses seated material and design state.

Runtime and CSS may express architecture.
They may not become architecture.

## Success Condition

Claude is operating correctly when:

- reviewer mode and executor mode remain distinct
- Cody-compatible execution happens only from OAR2
- deprecated Codex, runtime, and CSS surfaces are removed or neutralized before new runtime alignment
- isomorphic architecture is seated as authority before expression layers are structured
- OAR1 validates execution
- frontend, runtime, and CSS render seated state only

## c3 MAP Naming Update

Former working references to "golden audit" are renamed:

**c3 MAP — Measures Alignment Protocol**

c3 MAP is the native assessment route for this session. It diagnoses current system standing, identifies drift, and produces a Measures Resolution Map that routes required deprecations, contract corrections, Codex seating needs, runtime alignment, and CSS alignment.

c3 MAP does not define authority. It preserves Codex seating by mapping observed conditions into Measures resolutions, with execution routed only through approved OAR2 and completed only by validated OAR1 closeout.
