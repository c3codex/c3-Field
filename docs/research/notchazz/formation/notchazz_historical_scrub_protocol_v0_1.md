# NotChazz Historical Document Scrub Protocol v0.1

## Preservation rule

Do not edit, rename, relocate, normalize, or “correct” historical sources during the scrub. Produce derivatives with explicit lineage.

## Discovery terms

Primary exact variants:

- `NotChazz`
- `Not Chazz`
- `notchazz`

Relational expansion terms for a second pass:

- low-pass
- hold / held
- return to Current
- system intelligence
- boundary validation
- operator review required
- role collapse
- false continuity
- evidence before completion
- memory without authority

Expansion terms may generate false positives and must never be auto-classified as NotChazz.

## Source classification

The scrub classifies historical language without retroactively rewriting it. Any source that locates NotChazz ownership in Measures should be recorded as an ownership-model contribution or superseded architecture statement and compared with the controlling 2026-08-23 formation: c3Ops owns NotChazz; Measures only calls it through a governed relation.

| Class | Meaning |
|---|---|
| `primary_formation` | Forms or materially changes the NotChazz concept or role |
| `flag_instance` | Records one observed NotChazz flag |
| `resolution` | Records disposition, correction or resolved standing |
| `process_rule` | Generalizes a reusable trigger, hold or route |
| `environment_profile_candidate` | Identifies environment-specific applicability |
| `implementation` | Implements guard, matcher, preflight or runtime behavior |
| `evidence_return` | Returns execution evidence about a NotChazz-related action |
| `derivative` | Summarizes or normalizes prior sources |
| `citation_only` | Mentions NotChazz without materially contributing |
| `collision_or_unrelated` | Search hit not materially related |

## Required extracted fields

- source identity and title
- Drive ID and custody path/folder relation
- file date, declared version and standing
- named Operator, author, executor and reviewer
- exact NotChazz contribution
- flag class or process rule
- affected system, environment, role, operation and passage
- trigger and response
- authority boundary
- evidence and resolution relation
- upstream and downstream lineage
- duplicate or mirrored-custody relation
- attribution confidence
- normalization recommendation
- unresolved conflict or missing source

## Review order

1. Direct-title historical sources.
2. Dedicated NotChazz folders.
3. Source Concordance and operations manuals.
4. OAR2/OAR1 pairs and send.cards.
5. Implemented guards and tests.
6. Content-only search matches.
7. Relational-expansion candidates.

## Completion threshold

The scrub is complete only when every candidate is classified, mirrored copies are related rather than double-counted, primary formation sources are read directly, attribution conflicts are recorded, and the ledger contains a reviewable source relation for every normalized claim.
