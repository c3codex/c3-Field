## 2. Reappearance of identical content did not create authority

Execution evidence from the later Claude return records that the same OAR2 content had previously reached an executor receiving location and was held under Operator instruction. The file was left untouched and verified by hash.

The byte-identical OAR2 later appeared at a second CanCom path. Claude explicitly did **not** treat relocation/reappearance as fresh authorization. Execution proceeded only after direct Operator reconfirmation of the exact content.

### Historical contribution

This is a concrete custody/authority separation:

- same bytes can exist at multiple paths;
- relocation does not alter authority standing;
- repeated delivery does not convert a hold into authorization;
- hash identity permits the system to know that the object is the same while preserving the distinct standing of each passage event.

Normalized relation:

`same signal/object` can traverse a new path without inheriting a new permission state.

## 3. Parallel-executor collision relation

The governing OAR2 explicitly required validation against a Cody/Claude parallel-return incident. It records six controls:

1. two executors receiving the same operation require distinct execution IDs;
2. return directories and filenames must be executor- and execution-instance-qualified;
3. shared receipt paths must be rejected before live use;
4. overwrite refusal is a successful safety control but not successful completion;
5. review receipts remain separate from immutable executor returns;
6. Operator acceptance remains a separate final touch point.

### Historical contribution

This family demonstrates that a collision can be safely constrained without falsely reporting completion. Refusal to overwrite another executor's return is itself valid protective behavior, but it does not satisfy the authorized operation.

Normalized relation:

`protecting evidence integrity != completing the requested operation`.

The system must preserve both truths simultaneously.

## 4. Hashes as relation-binding evidence

The Claude return recorded hashes for generated working artifacts and for the execution-instance-qualified return. The historical source also recognized a self-hash boundary: a manifest cannot contain its own post-write hash.

This family therefore uses hashes for bounded purposes:

- object identity;
- proof that a held and later-routed OAR2 are byte-identical;
- binding explicit authorization to reviewed content;
- binding return artifacts to an execution instance;
- detecting overwrite/custody divergence.

Hashes do **not** establish authority, acceptance, semantic correctness, or final standing by themselves.
