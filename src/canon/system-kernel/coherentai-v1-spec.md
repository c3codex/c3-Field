# CoherentAI v1.0 — System Specification

**Status:** Canon Candidate (v1)  
**Audience:** Technical but accessible  
**Scope:** Defines the minimum viable CoherentAI system used by c3 / Priceless Gallery to serve canon, route meaning, and protect integrity.

---

## 1. Purpose

CoherentAI v1.0 is a canon-aware knowledge interface built to:

- **Serve canonical documents and artifacts** reliably (publicly readable, tamper-evident)
- **Link canon to concepts** (so the system can explain "what this belongs to")
- **Route observations through OAR logic** (Observed · Aligned · Routed) as an append-only trace
- **Deliver private files securely** (private storage + signed URLs)
- **Support the c3 model** (Connect · Contribute · Create) with a structured, auditable foundation

CoherentAI is not defined by "chat."  
It is defined by **artifacts, links, and rules**.

---

## 2. Architecture Overview

CoherentAI v1.0 is implemented using:

- **Supabase Postgres** (canonical tables + relations)
- **Supabase Storage** (private bucket `codex-vault`)
- **Row Level Security (RLS)** (public reads, restricted writes)
- **Edge Functions / Server endpoints** (signed URL generation, canon resolution)
- **Frontend UI** (Connect pillar entry point)

---

## 3. Canon Registry

Canon artifacts are registered in `public.canon_artifact`.

Each canon artifact is identified by a **slug** and typically includes:

- `slug` (stable identifier)
- `title`
- `type` (doc, image, other)
- `visibility` (e.g., `sealed`)
- `scope` (public/internal)
- storage paths (md + pdf when applicable)

### Private storage, public delivery

Canon documents are stored in a private bucket:

- bucket: `codex-vault`
- objects: `canon_docs/<slug>.md` and `canon_docs/<slug>.pdf`

Because storage is private, public delivery is performed through **signed URLs** generated by a resolver endpoint.

**Design intent:** the world can read canon, but cannot scrape or mutate the vault.

---

## 4. Canon Integrity Model

CoherentAI treats canon as "readable and auditable" rather than "editable."

### Sealed behavior

When `visibility = 'sealed'`:

- updates are blocked (guarded)
- deletion is blocked (guarded)
- the artifact becomes immutable as a registry entry

### Hashing

Where available, hashes are recorded to make canon tamper-evident:

- A single `hash` field (legacy/simple)
- Or md/pdf hashes via a manifest layer (recommended)

v1 supports hash recording and sealing logic; full automated verification may expand in later versions.

---

## 5. Concepts and Linkage

Concepts live in `public.concept`.

Artifacts link to concepts through `public.artifact_concept`.

### Primary vs Supporting links

Each canon artifact should have:

- **1 primary concept link** (the artifact's own identity)
- **1+ supporting concept links** (umbrella concepts and thematic anchors)

`artifact_concept.link_role` is used to distinguish:

- `primary`
- `supporting`

This enables CoherentAI to answer:

- "what is this artifact?"
- "what larger system does it belong to?"
- "what governance principles does it activate?"

---

## 6. OAR Routing Engine

OAR = **Observed · Aligned · Routed**

Table: `public.oar_log`

Fields include:

- `observed` (what happened / what is seen)
- `aligned` (why it matters / what it matches)
- `routed` (structured JSON output, including links and actions)
- optional `pillar` + `container`
- `confidence` (numeric)

### Append-only enforcement

OAR is append-only:

- no updates
- no deletes

Corrections are made by inserting a new OAR entry that references the prior entry (an "amends" link).

**Design intent:** reasoning and governance traces should be auditable over time.

---

## 7. Release Model

CoherentAI supports phased releases through:

- `releases`
- `release_items`
- optional `ritual_marker`

This allows canon and exhibits to be delivered on a schedule without altering canonical history.

- `coherent_convergence_whitepaper`
- `field_emergence_whitepaper`
- `recognition_as_protocol_whitepaper`

These dependencies are referenced by slug in the canon registry and resolved to md/pdf assets via signed URLs.

---

## 9. Definition of CoherentAI v1.0

CoherentAI v1.0 is defined as the minimum complete system that provides:

- a canon registry with immutable behavior for sealed entries
- private storage with signed public delivery
- concept linkage with primary/supporting semantics
- append-only OAR routing logs
- release scaffolding for phased ritual publication

This version establishes integrity before expansion.
