## What the c3 Model Is

The c3 Model is the **living circuit** that governs how value flows across the entire c3 Field.

It is not a marketing framework.  
It is not a product funnel.  
It is the **weave** — the west-facing pillar of Codexstone that holds the structural logic through which all other pillars operate.

The circuit is:

```
Connect → Contribute → Create
```

Every initiative, pillar, and system in c3 Field is governed by this pattern. The c3 Model pillar is the canonical surface where that pattern is defined, documented, and made legible.

---

## Circuit Definitions

### Connect
Read-only encounter. Orientation without coercion.

Value enters here as attention, presence, and recognition — not transaction. No state changes. No extraction. Trust is established before participation is invited.

### Contribute
Voluntary value entry. Structured participation without extraction.

Value enters the system through defined, transparent pathways. Contribution is registered, attributed, and split through immutable rules. No negotiation. No speculation.

### Create
Governed execution. Commons realization through stewarded structure.

Accumulated value becomes real-world structure — land, space, infrastructure, stability. Execution is governed. Decisions are auditable. The commons is restored materially.

---

## Structural Logic

The c3 Model is the primary expression of the **Weave** — the pattern that holds all pillars in coherent relation.

It maps across every operating layer of the field:

| Layer | Pattern |
|---|---|
| Civic | Connect → Contribute → Create |
| Operational | Objective → Action → Result |
| State | Orientation → Alignment → Realization |
| Measures | Descent → Recognition → Integration |
| Structural | Source → Passage → Form |

These are not separate systems. They are the same circuit viewed through different lenses.

---

## Canonical Constraints

The following are binding constraints that may not be overridden by implementation decisions:

1. **The circuit sequence is immutable.** Connect always precedes Contribute. Contribute always precedes Create. No step may be skipped or reordered.
2. **Connect is read-only.** No state changes, no wallet requirements, no coercive elements at the encounter layer.
3. **Contribute is voluntary.** No minimums, no suggested values, no negotiation.
4. **Create is governed.** Commons allocation requires DAO authorization. Execution is logged and auditable.
5. **The c3 Model does not curate content.** It governs circulation and structure — not creative direction.
6. **SQL governance aligns to the circuit.** CONNECT = Read. CONTRIBUTE = Write. CREATE = Migrate.

## Pillar Boundaries

The c3 Model is **the governing circuit** for all pillars and is therefore structurally distinct from them.

It may:
- define the circulation logic that all other pillars inherit
- surface as a legible reference within the Codexstone container
- govern how value moves between Measures, Priceless Gallery, and c3 Community Partners

It may not:
- be collapsed into any single pillar's implementation
- be overridden by initiative-level decisions
- become a promotional or marketing surface
