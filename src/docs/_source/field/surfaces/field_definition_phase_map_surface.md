# Field Definition — Phase Map (Relational Positioning Surface)

## Purpose

Seat Phase Map in Field as the relational positioning surface that becomes available after first encounter.

Phase Map does not initiate passage.
Phase Map does not render encounter.

Phase Map reveals where signal stands in relation to what may be encountered next.

## Field Role

Phase Map resolves as:

- relational positioning surface
- encounter visibility layer
- adjacency and dependency expression surface
- progression awareness surface

Phase Map does not resolve as:

- intake surface
- passage mechanism
- encounter surface
- Codex authority
- Measures registry

## Structural Relations

Phase Map must relate to:

- Epigraph as prior encounter surface
- Obsidian Chamber as current material context
- Harrumuk Passage as resolved entry condition
- Antechamber as origin state
- Envelope as carried signal structure
- envKey as access continuity
- OAR1 / OAR2 as trace surfaces
- Relational Nodes as position points
- Relational Vectors as directional relations
- NotChazz as constraint enforcement

## Entry Condition

Phase Map becomes available only when:

- Epigraph has rendered
- signal has stabilized within Obsidian
- passage has already resolved
- NotChazz permits relational visibility

If these are not true:

? Phase Map does not appear
? no relational navigation is available

## Functional Behavior

Phase Map performs:

- positioning of current signal state
- exposure of adjacent encounters
- indication of available progression paths
- visibility into dependency relationships

Phase Map does not:

- move signal
- trigger passage
- override sequence
- simulate availability

## Relational Structure

Phase Map expresses:

- Relational Nodes ? where signal is placed
- Relational Vectors ? how signal may move
- Dependencies ? what must resolve before movement
- Phase State ? current availability condition

All relations must resolve through Field structure.

## Boundary Rule

Phase Map may:

- reveal what is available
- show relation
- expose adjacency

Phase Map may not:

- bypass sequence
- unlock sealed states
- simulate progression
- expose unavailable encounters

## Transition Rule

Phase Map does not initiate movement.

Movement from Phase Map requires:

- valid relation
- satisfied dependency
- permitted progression

Then:

Phase Map ? next valid encounter (via Measures)

## Failure State

If signal is not properly positioned:

- Phase Map does not render
- or renders restricted state
- progression is not available

No false visibility.
No simulated options.

## Protection Relation

NotChazz must be able to:

- restrict invalid visibility
- prevent exposure of unreleased states
- enforce dependency conditions
- preserve structural integrity

## Success Condition

Phase Map is properly seated in Field when:

- it appears only after encounter
- it reflects true relational position
- it exposes only valid next states
- it does not initiate or simulate movement
- it preserves dependency integrity

## Closing

Phase Map does not move the signal.

It reveals where the signal stands.

It is not the path.
It is the awareness of the path.

Codex holds.
Field structures.
Measures registers.
Chazz operates.
NotChazz protects.
