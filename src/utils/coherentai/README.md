# CoherentAI

CoherentAI is a governance-support system designed to operate within a defined structural field.

It does not define structure.
It does not own routing.
It does not override domain boundaries.

It supports pillars.

---

## Purpose

CoherentAI provides:

- Canon registry validation
- Append-only reasoning traces (OAR)
- Concept linkage verification
- Drift detection and coherence checks
- Optional LLM-assisted analysis (bounded and logged)

It operates as a **System**, not a Pillar.

Structure precedes intelligence.
Verification precedes delegation.

---

## Architectural Role

Within the c3 Field repository, all code must fall into one of three categories:

1. Structure — serves Codexstone (law and hierarchy)
2. Pillar — domain-bound logic
3. System — supporting intelligence

CoherentAI lives in: 
It may:

- Read structural contracts
- Validate domain state
- Log append-only traces
- Assist learning or indexing

It may not:

- Define navigation
- Own top-level routes
- Import pillar logic
- Redefine canonical hierarchy

---

## Core Components

### Kernel'
Deterministic coherence verification engine.

### OAR Logger
Append-only reasoning trace mechanism.

### Validators
Checks for:
- Missing assets
- Drift from canonical geometry
- Calendar integrity
- Structural violations

### Adapters
Interfaces to:
- Supabase
- LLM providers
- External indexing systems

---

## Determinism First

CoherentAI logic must always be deterministic before LLM-assisted.

LLM calls are:
- Optional
- Logged
- Bounded
- Non-authoritative

The LLM never defines coherence.
It may analyze within geometric constraints.

---

## Git vs Supabase

Structural contracts live in Git.

Operational state lives in Supabase.

CoherentAI reads state.
It does not redefine structure.
